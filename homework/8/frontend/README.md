# Рабочий интерфейс ДЗ 8

React + TypeScript + Vite, shadcn/ui (Base UI), Tailwind CSS. Интерфейс перенесён из экспорта v0, сохранённого в `../prototype/`. Общая тема, цвета, шрифты и отступы — `src/styles.css` и классы компонентов. Демопанель и имитация запросов остались только в прототипе; поиск здесь выполняется настоящим GET-запросом к n8n.

## Запуск

Node.js 22.12+ или 24 LTS, pnpm. Из этой папки:

```powershell
pnpm install --frozen-lockfile
Copy-Item .env.example .env.local
pnpm dev
```

Адрес: `http://127.0.0.1:5173`. В `.env.local` задаётся `VITE_ITEMS_WEBHOOK_URL` — Production URL опубликованного workflow. После изменения переменной перезапустить Vite. Это публичный адрес API, не секрет; VITE-переменные входят в клиентскую сборку. Пароли и ключи здесь не нужны.

```powershell
pnpm build
pnpm preview
```

Сборка включает проверку TypeScript. API описан в `../api-contract.md`, workflow — в `../workflows/`. Приложение не использует dev-proxy: браузер обращается непосредственно к n8n с CORS.

## Проверка сценария

`alp` → Alpha; `GA` → Gamma и Omega; `zzz` → пустой результат; пустая строка → пять элементов. `@@@`, кириллица или 41 символ → ошибка у поля без запроса. Исправление ввода снимает старую ошибку. Результаты подписаны запросом, для которого они получены.

При загрузке предыдущий список сохраняется, повторная отправка блокируется также синхронной ссылкой на активный запрос. Сброс отменяет запрос и возвращает исходный список и фокус. Запоздалый ответ после сброса игнорируется. Поле можно редактировать во время ожидания: результат относится к отправленному значению, а подсказка показывает наличие нового ввода.

При HTTP/сетевой ошибке или неправильном JSON сохраняются ввод и предыдущие результаты. Повтор отправляет текущее поле. Таймаут — 15 секунд. Для проверки сетевого сбоя можно включить Offline в DevTools, отправить форму, затем вернуть сеть и повторить; искусственных сбоев в рабочем API нет.

Начальный список и сброс используют фиксированный исходный набор из предыдущего проекта. Каждый поиск, включая пустую строку, получает результат из n8n. Клиентская валидация помогает пользователю, серверная независимо проверяет запрос.

Клиентские тесты добавлены: Vitest + Testing Library + MSW, браузерные сценарии Playwright Test. Подробности — в ../testing.md. Полная подготовка материалов защиты — следующий этап. Локальная проверка Code-нод workflow: `node ../tests/check-workflow.cjs`.

## Клиентские тесты

```powershell
pnpm test
pnpm test:e2e
pnpm test:all
pnpm test:quality
```

Vitest/MSW подменяют HTTP-ответы; Playwright Test запускает Chrome на desktop/mobile с подменой сети и отдельным сервером на 5174. Работающий n8n для этих команд не нужен. `test:quality` временно скрывает ошибку, подтверждает падение теста, восстанавливает исходник и подтверждает прохождение. Запускать отдельно от редактирования и других тестов.

Для браузерных тестов нужен Chrome, либо `pnpm exec playwright install chromium` и `$env:PW_CHANNEL = 'chromium'`. Подробности и соответствие критериям — [testing.md](../testing.md). Записанные результаты — в `../test-evidence/`.
