# AI-прототип и история исправлений

Для дальнейшей разработки выбран прототип v0. Пользователь предоставил первый экспорт `project.zip` и скриншот, затем обновлённый `project (1).zip` после обсуждения исправлений. Обновлённый экспорт сохранён в `prototype/v0-export.zip`, исходники — в `prototype/v0/`. Предварительный HTML-вариант Codex заменён экспортом v0.

## Что сделал AI

v0 создал React-интерфейс: форму поиска, карточку правил с примерами, результаты, подсветку совпадений, счётчик символов, состояния и отдельную демонстрационную панель. Использованы компоненты shadcn/ui, светлая тема с зелёным акцентом, общий набор стилей Tailwind. Экспорт создан на Next.js; для рабочей версии запланирован React + TypeScript + Vite.

Codex подготовил спецификацию и запросы для v0, проверил исходники обоих экспортов, предложил исправления и задокументировал результат. Пользователь выбрал инструмент, передал экспорты и инициировал доработку. Эти действия не означают, что все сценарии уже подтверждены браузерными тестами.

## Запросы для v0

Ниже сохранены тексты, предложенные пользователю в чате. История самого чата v0 не предоставлена, поэтому точное совпадение отправленного текста и состав прикреплённых файлов не подтверждены.

### Основной запрос

```text
Создай интерактивный прототип приложения «Валидатор строк».
Используй React, TypeScript, shadcn/ui и Tailwind CSS.
Весь интерфейс на русском.

Компоновка: слева форма поиска и правила, справа список результатов.
Светлая тема с зелёным акцентом, аккуратная типографика.
На мобильном экране одна колонка.

Данные: Alpha, Beta, Gamma, Delta, Omega.

Правила:
- Допустимы латинские буквы, цифры и пробельные символы.
- Максимум 40 символов. Не обрезай ввод автоматически.
- Пустая строка допустима и показывает весь список.
- Поиск по подстроке без учёта регистра.
- Отправка кнопкой «Проверить и найти» или Enter.
- «Сбросить» очищает поле, возвращает весь список и фокус в поле.

Покажи состояния: исходное, загрузка, успех, нет совпадений,
ошибка валидации и ошибка запроса с кнопкой повтора.
При ошибке сохраняй ввод.
Во время загрузки блокируй повторную отправку.
Имитируй запрос задержкой 900 мс, настоящий backend пока не нужен.

Добавь отдельную панель демонстрации состояний с явной
пометкой «Только для прототипа».
Используй label, доступные сообщения об ошибках,
видимый фокус и управление клавиатурой.

Не добавляй авторизацию, базу данных и дополнительные страницы.
```

Дополнение об исходниках:

```text
Это исходная реализация валидатора и его контракт. Используй их как
основу поведения. Создай новый интерфейс на React, TypeScript и shadcn/ui
по описанию ниже. Поиск — по кнопке или Enter. Пока нужен прототип
с имитацией запросов, без настоящего API.
```

Было рекомендовано приложить `string-validator/ui/index.html`, `app.js`, `items.json` и `string-validator/contract.md`.

### Запрос на исправления

```text
Сохрани текущий дизайн и исправь поведение:

1. Если поле отличается от последнего отправленного запроса,
показывай: «Запрос изменён. Нажмите “Проверить и найти”».
Явно обозначай, к какому запросу относятся текущие результаты.

2. При редактировании поля снимай ошибку предыдущей валидации.
Повторно проверяй ввод при отправке.

3. В validateQuery и filterItems отдельно проверяй
query.length <= 40 и допустимость всех символов.
Не полагайся только на regex с конечным $.
Пустая строка по-прежнему допустима, ввод не обрезай.

4. Во время загрузки сохраняй предыдущий список результатов
с индикатором ожидания. При сетевой ошибке также сохраняй
последний успешный список и введённый текст.

5. Кнопка «Повторить» должна отправлять текущее значение поля.
Сохрани защиту от повторной отправки во время запроса.

Стек и внешний вид сейчас не меняй. Настоящий API не добавляй.
```

## Что изменилось по результатам проверки исходников

| Замечание к первому экспорту | Обновлённый экспорт |
|---|---|
| Старый результат выглядел связанным с новым вводом | Разделены текущий ввод, последний отправленный запрос и запрос результата; добавлено пояснение |
| Ошибка валидации оставалась после правки | Обработчик изменения снимает предыдущую ошибку |
| Regex мог пропустить 40 букв и завершающий перевод строки | Длина проверяется отдельно; допустимость проверяется для каждого символа |
| При ожидании и сетевой ошибке список исчезал | Сохранены последние результаты с подписью запроса |
| Повтор использовал предыдущий запрос | Повтор передаёт текущее значение поля |

Уточнение поведения: обновлённый прототип сохраняет прежний список также при ошибке валидации. Поле и сброс доступны во время ожидания; сброс отменяет имитируемый запрос. Повторная отправка блокируется кнопкой и синхронной проверкой ссылки на активный AbortController. Спецификация приведена к этому варианту; отмена и отсутствие устаревших ответов должны быть проверены при реализации.

## Дальнейшая работа и границы подтверждения

Пользователь поручил сохранить прототип как основу следующих этапов. Зафиксирован исходный экспорт, а не изменённая вручную копия. Прочитаны исходники и просмотрен предоставленный скриншот первой версии. Установка пакетов, сборка, автоматические тесты и браузерная проверка обновлённой версии при архивировании не выполнялись.

Будущая рабочая цепочка: React → webhook n8n → валидация и фильтрация → ответ интерфейсу. Прототип остаётся на имитируемых данных. Для защиты предстоит показать рабочую интеграцию, доступность, соответствие прототипу и клиентские тесты с подменой ответов; отдельно проверить, что намеренная поломка поведения вызывает падение соответствующего теста.


На этапе клиентских тестов обнаружено и исправлено смещение кнопок на мобильном экране при исчезновении подсказки. В рабочей версии сохранена высота области статуса; экспорт прототипа остаётся исходным. Проверка двойного клика проходит на desktop/mobile. Проверки, результаты и эксперимент с намеренной поломкой описаны в testing.md и test-evidence/.
