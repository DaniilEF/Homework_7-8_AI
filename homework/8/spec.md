# Спецификация интерфейса валидатора строк

Статус: основа реализации после выбора прототипа v0; экспорт сохранён в prototype/. Рабочий React/Vite-интерфейс в frontend/ подключён к опубликованному webhook n8n; сборка и браузерная проверка интеграции прошли. Клиентские проверки добавлены и прошли: 25 Vitest/MSW и 4 Playwright; проверка намеренной поломки и восстановления подтверждена в test-evidence/.

## Сценарий

Пользователь проверяет строку поиска и находит элементы существующего списка. Вводит запрос, нажимает «Проверить и найти» либо Enter и видит результат проверки и список совпадений. Исходные данные: Alpha, Beta, Gamma, Delta, Omega из string-validator/ui/items.json.

Изменение взаимодействия относительно практики 5: вместо фильтрации на каждый input используется явная отправка формы. Такой вариант включён в выбранный прототип v0. Инварианты предметной логики сохраняются.

## Правила

- Пустой запрос допустим и возвращает исходный список. Поле намеренно не required: искусственно запрещать пустую строку нельзя.
- Допустимы латинские буквы, цифры и пробельные символы из исходного контракта (`\s`). Кириллица и спецсимволы не принимаются. Поле интерфейса однострочное.
- Максимум 40 символов. Реализация должна проверять длину отдельно: исходный regex с `$` может пропустить 40 букв и завершающий перевод строки. В обновлённом экспорте v0 длина проверяется отдельно; граничные случаи предстоит подтвердить тестами.
- Подстрочный поиск без учёта регистра. Пробелы не обрезаются автоматически; в запрос передаётся точное значение поля.
- Ввод длиннее 40 не обрезается: счётчик и ошибка объясняют причину отказа.
- Произвольные введённые строки выводятся как текст, без исполнения HTML.

## Состояния

| Состояние | Видимое поведение |
|---|---|
| Исходное | Пустое поле, счётчик 0/40, весь список, нейтральная подсказка |
| Ввод | Поле и счётчик меняются, предыдущий список сохраняется; сообщение поясняет, что новый запрос ещё не применён |
| Загрузка | Индикатор и «Проверяем…»; высота области статуса сохранена, чтобы кнопки не смещались под повторным кликом; результаты busy, повторная отправка недоступна; поле доступно, сброс отменяет запрос; предыдущий список остаётся видимым |
| Успех | Подтверждение валидности, точный применённый запрос и число совпадений |
| Пустой результат | Строка валидна, но совпадений нет; предложение изменить запрос или сбросить |
| Ошибка ввода | Ошибка у поля, aria-invalid=true; точный ввод и прежние результаты сохранены; при редактировании предыдущая ошибка снимается |
| Ошибка запроса | Понятное уведомление и «Повторить запрос»; ввод сохранён, последний успешный список остаётся видимым |

При редактировании поля результат не должен выглядеть применённым к новому значению до отправки. Сброс очищает запрос и ошибки, возвращает исходный список и фокус в поле. Поиск zzz: пустой результат; alp: Alpha; GA: Gamma и Omega; @@@: ошибка ввода.

## Запросы и защита повторов

Для будущей рабочей версии планируется GET /api/items?query=… с encodeURIComponent, серверная логика фильтра и локальная проверка ввода на клиенте. Успех: `{items:[{id,name}]}`. Ошибка валидации: HTTP 400, `{error:{code:'INVALID_FILTER',message:'…'}}`. В рабочей версии запрос будет направляться в webhook n8n (адрес через настройку окружения). Сетевой сбой/500 — состояние ошибки запроса. Формат закреплён в api-contract.md; JSON workflow и локальные проверки Code-нод находятся в workflows/ и tests/. Реальные HTTP-ответы и браузерная интеграция проверены 18 ноября 2026.

Асинхронная отправка имеет один pending-флаг, проверяемый в начале обработчика submit. Двойной клик, повтор Enter и программное повторное submit во время ожидания не создают дополнительного запроса. Флаг снимается и после успеха, и после ошибки. Ошибка не очищает ввод. Кнопка повтора отправляет текущее значение поля. Сброс отменяет ожидание; отменённый ответ не должен менять интерфейс. В прототипе сервер имитируется таймером; это не рабочее API и не доказательство реализации ДЗ.

## Доступность и адаптивность

Явный label, подсказка через aria-describedby, ошибки aria-live/role=alert, состояние aria-busy, видимый focus-visible. Кнопки имеют правильные type. Порядок Tab соответствует форме, основные действия работают с клавиатуры. После невалидной отправки фокус возвращается в поле; после сброса тоже. На мобильном экране блоки идут одной колонкой без горизонтальной прокрутки.

## Компоненты и тема будущей реализации

React + TypeScript + Vite; shadcn/ui: Button, Input, Card, Badge, Alert, Separator и Skeleton при необходимости. Экспорт v0 использует React + TypeScript + Next.js и компоненты shadcn/ui; при переносе на Vite сохраняем их оформление. Светлый фон, тёмный текст, зелёный акцент, единая шкала отступов. Декоративные элементы не заменяют подписи и состояния.

## Критерии приёмки будущей реализации

1. alp → Alpha, GA → Gamma и Omega, пустая строка → пять исходных элементов.
2. @@@, кириллица и длина 41 → ошибка; 40 допустимых символов принимаются.
3. Во время задержки повторные действия дают ровно один запрос.
4. При 500/сетевой ошибке ввод сохраняется; повтор может успешно завершиться.
5. Пустой ответ показывает пустое состояние, а не ошибку.
6. Сброс возвращает весь список и фокус в поле.
7. Основной путь от ввода до результата проходит автоматический клиентский тест.
8. Тесты проверяют видимый результат, подменяют успех/пустой ответ/задержку/ошибку и падают при намеренном нарушении поведения.
9. Макет сравнивается с реализацией на широком и узком экране. До согласования эталонные скриншоты не объявляются утверждёнными.
