# API валидатора строк — ДЗ 8

Рабочая цепочка: React → GET webhook n8n → проверка запроса → валидация и фильтрация → JSON-ответ. Workflow: `workflows/HW 8 — String Validator API.json`.

## Запрос

```http
GET <webhook-url>?query=alp
```

`<webhook-url>` копируется из ноды Items Webhook; production path — `hw8-string-validator-items`. Параметр `query` обязателен и должен быть одной строкой. Для полного списка передаётся `?query=`. Значение кодируется через `encodeURIComponent(query)` без trim и обрезки. Тело запроса не используется.

Клиент вызывает `fetch(url)` без cookies, токенов и дополнительных заголовков. URL собирается через `URL`/`searchParams.set('query', query)` либо с корректным `encodeURIComponent`. Встроенный JSON-декодер fetch читает ответ. Установка Content-Type на GET не требуется.

Пример будущего клиентского вызова:

```ts
const url = new URL(import.meta.env.VITE_ITEMS_WEBHOOK_URL)
url.searchParams.set('query', query)
const response = await fetch(url, { signal })
const body = await response.json()
// Проверять response.ok и формат body перед обновлением интерфейса.
```

В рабочем фронтенде адрес будет задаваться через `VITE_ITEMS_WEBHOOK_URL`. Рабочий фронтенд в frontend/ выполняет настоящий fetch; сохранённый экспорт в prototype/ использует имитацию.

## Ответы

HTTP 200 для `alp`:

```json
{"items":[{"id":"1","name":"Alpha"}]}
```

HTTP 200 без совпадений:

```json
{"items":[]}
```

HTTP 400 для недопустимого фильтра:

```json
{"error":{"code":"INVALID_FILTER","message":"Недопустимый фильтр. Используйте латинские буквы, цифры и пробельные символы, до 40 символов."}}
```

HTTP 400, если `query` отсутствует либо декодирован как массив/объект вместо строки:

```json
{"error":{"code":"INVALID_REQUEST","message":"Передайте один строковый параметр query. Для полного списка используйте query=."}}
```

Коды `statusCode` и обёртка `body` существуют только между нодами n8n. Клиент получает непосредственно `{items: ...}` или `{error: ...}`, без массива n8n items и без внутренней обёртки.

## Правила

Допустимы латинские буквы, цифры и символы JavaScript `\s`. Длина — не более 40 кодовых единиц UTF-16 (`query.length`), проверяется отдельно. Однострочный UI не даёт вводить переводы строки, но серверный контракт сохраняет исходное правило для пробельных символов. Пустая строка допустима. Поиск по подстроке без учёта регистра. Пробелы не удаляются.

Исходные элементы совпадают с `string-validator/ui/items.json`: Alpha, Beta, Gamma, Delta, Omega; id — строки от `1` до `5`. Например, `GA` находит Gamma и Omega: обе строки содержат `ga` без учёта регистра. Прежний пример «GA → Gamma» перечислял не все совпадения. Данные находятся в ноде Validate and Filter, доступны без credentials и не изменяются запросами. Нет искусственной задержки, переключателя ошибки и вызова AI.

Ошибки платформы n8n или прокси (например 404 для неопубликованного webhook, 500 либо HTML вместо JSON) могут иметь иной формат. Фронтенд должен отобразить ошибку запроса, сохранить ввод/предыдущий результат и дать повторить. Для 400 показывается ошибка валидации или некорректного запроса, а не пустой результат.

Ответы workflow содержат `Access-Control-Allow-Origin: *` для вызова этого публичного учебного API из локального фронтенда и `Cache-Control: no-store`. Запрос не использует credentials. Для GET без нестандартных заголовков preflight не нужен. CORS на ошибках платформы зависит от сервера n8n/прокси и проверяется после импорта.

```powershell
node homework/8/tests/check-workflow.cjs
```

Проверка исполняет код двух Code-нод из самого JSON, сверяет данные с исходным items.json, HTTP-коды и формы ответов. Это локальная проверка экспортированной логики, а не запуск в n8n и не клиентские тесты ДЗ 8. 18 ноября 2026 опубликованный endpoint проверен реальными HTTP-запросами (alp, GA, zzz, пустая строка, @@@) и браузерным сценарием из frontend/smoke-live.mjs; успешные ответы и ошибка валидации соответствуют контракту.
