# Клиентские тесты ДЗ 8

## Запуск

Из `homework/8/frontend` после `pnpm install --frozen-lockfile`:

```powershell
pnpm test
pnpm test:e2e
pnpm test:all
pnpm test:quality
pnpm build
```

`pnpm test` запускает Vitest, Testing Library и MSW в jsdom. `pnpm test:e2e` запускает Playwright Test: два сценария на двух конфигурациях экрана (desktop и mobile), всего четыре проверки. `pnpm test:all` последовательно запускает оба набора. `pnpm test:watch` оставляет Vitest в режиме наблюдения.

Для браузерных тестов по умолчанию используется установленный Google Chrome. Если Chrome отсутствует:

```powershell
pnpm exec playwright install chromium
$env:PW_CHANNEL = 'chromium'
pnpm test:e2e
```

Playwright сам запускает отдельный Vite на `127.0.0.1:5174`, затем останавливает его. Порт должен быть свободен. Рабочий интерфейс на `5173` и прототип на `3000` не используются тестами. Мобильная конфигурация — эмуляция iPhone 13 в Chromium, не проверка настоящего iOS Safari.

## Что проверяется

| Критерий | Файл и наблюдаемый результат |
|---|---|
| Компоненты | `tests/interface.test.tsx`: форма с доступной подписью, кнопки, правила, счётчик и пять элементов |
| Взаимодействия | Пример заполняет поле без запроса; Enter отправляет; сброс очищает поле и возвращает фокус |
| Полный клиентский сценарий | Заполнение → HTTP-ответ → список; в Playwright также пустой результат, неверный ввод и сброс |
| Данные действительно взяты из ответа | Тест возвращает Remote match, отсутствующий в локальном наборе; UI показывает именно его |
| Валидация | Спецсимволы, кириллица, 41 символ; ошибка видна, ввод сохранён и запрос не отправляется; редактирование снимает ошибку |
| Границы | 40 допустимых символов принимаются; 40 букв и завершающий перевод строки отвергаются; пробелы не обрезаются |
| Пустой запрос | Допустим по контракту: поле не required, отправляется пустая строка, отображается ответ |
| Загрузка и повторы | Ответ удерживается управляемым Promise; видна загрузка, старый список сохранён; двойной клик и повторный Enter дают один запрос |
| Защита до перерисовки | Два submit в одном act дают один запрос — проверяется синхронный guard, а не только disabled кнопки |
| Успех и пустые данные | HTTP 200 с items и с пустым массивом показывают разные состояния |
| Ошибки | HTTP 400, HTTP 500, сетевой сбой; сохранение ввода/списка и повтор с текущим значением |
| Отмена | Сброс отменяет старый запрос; поздний ответ не должен заменить новый результат |
| Контракт | `tests/api.test.ts`: неверные типы id/name, дубли id, неправильная обёртка и не-JSON ответ дают ошибку |
| Узкий экран и клавиатура | `e2e/scenario.spec.ts`: Tab/Enter, видимый результат, фокус, отсутствие горизонтальной прокрутки |

Диалогов в пользовательском сценарии нет, поэтому тестов открытия/закрытия диалога не добавлено. Обязательное поле искусственно не вводилось: пустая строка валидна по контракту проекта.

## Как подменяются ответы

Тесты не подменяют функцию поиска и не используют локальный фильтр для вычисления ожидаемого результата. Настоящий клиентский `fetch` выполняется, а HTTP-граница перехватывается:

- Vitest: MSW `setupServer`, `http.get` и `HttpResponse.json` в `tests/server.ts` и отдельных тестах.
- Playwright: `page.route` и `route.fulfill` в `e2e/scenario.spec.ts`.

Адрес в обоих наборах — `https://validator.test/items`; это тестовая настройка, не опубликованный n8n. Запросы не должны попадать в рабочий webhook. В MSW незарегистрированные запросы запрещены через `onUnhandledFrame: 'error'` (API MSW 3).

Фикстуры повторяют реальный контракт: `{items:[{id:"1",name:"Alpha"}]}`, `{items:[]}`, `{error:{code:"INVALID_FILTER",message:"…"}}` с HTTP 400. Сбой HTTP 500 моделируется отдельно. Фикстуры успеха содержат самостоятельные ожидаемые данные, а не результат вызова проверяемой функции фильтра.

Задержка управляется Promise, который тест освобождает после проверок загрузки и числа запросов. Это позволяет проверять состояние ожидания без произвольных sleep и обращения к настоящему серверу.

Интеграция с настоящим n8n проверяется отдельно командой `pnpm test:live`, при запущенном приложении на `5173`. Этот запуск не входит в изолированный клиентский набор и требует сети и опубликованного workflow.

## Проверка качества AI-тестов

`pnpm test:quality` запускает `verify-test-quality.mjs`:

1. Сохраняет исходные байты SearchForm.
2. Временно отключает только отображение ошибки валидации.
3. Запускает три проверки неверного ввода. Они должны упасть из-за отсутствия видимого alert.
4. В finally восстанавливает исходный файл и проверяет его SHA-256.
5. Запускает те же три проверки повторно; они должны пройти.

Логи и JSON-результат записываются в `../test-evidence/`. Не запускать эту команду одновременно с редактированием SearchForm или другими тестами. Во время проверки сообщение об ошибке временно скрывается и в работающем dev-сервере. Команда проверяет одну осознанную поломку, а не полноту всех возможных мутаций.

## Вклад AI и исправления после запуска

Запрос пользователя: «вперед пункт 5» после согласования Vitest + Testing Library, MSW и Playwright Test. AI подготовил сценарии, независимые фикстуры, настройки, команды и скрипт проверки качества.

При проверке тестового кода исправлены параметры Testing Library (у getByRole нет опции exact), настройка актуального MSW 3 и совместимость TypeScript с ним. Это исправления тестового окружения, а не замена ожидаемого поведения приложения.

Браузерный тест выявил реальный дефект мобильного интерфейса: после отправки исчезало сообщение об изменённом запросе, кнопки смещались, второй клик мог попасть на сброс. В SearchForm зарезервирована высота области статуса; проверка повторной отправки после исправления проходит и на мобильном экране. Сохранённый экспорт v0 не изменён; рабочая версия отличается этим исправлением и уже описанной интеграцией с n8n.
